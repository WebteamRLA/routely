Routely — Testing Guide

A step-by-step walkthrough for checking that Routely works. No technical knowledge assumed — but you will need someone who can add a line of code to your website for one step, and that step is clearly marked.

Test site: https://routely-nine.vercel.app  ·  Print this and tick as you go. Allow about 45 minutes.

What Routely does

Routely answers one question: if I send half my visitors to a different page, do more of them do the thing I want?

You give it three web addresses:

The control page The page you have now. Half your visitors carry on seeing it.
The variant page The alternative you want to try. The other half get sent here instead.
The goal page The page that means success — a thank-you page, an order confirmation. Reaching it counts as a win.

Routely then tells you which half reached the goal more often.

Before you start

Please have these ready. Without them you will get stuck at test 3.

  • A Google account to sign in with.
  • A website you can edit. You need to be able to add a small piece of code to it — or have someone nearby who can. A WordPress site, Wix, Squarespace or a normal HTML site all work.
  • Three pages on that website, all real pages that open in a browser: the page you want to test, an alternative version of it, and a page that counts as success. For example /pricing, /pricing-new and /thank-you.

The most common reason testing fails

All three pages must already exist and open normally in your browser before you start. If typing the address into a browser gives you a "page not found", Routely cannot test it — and no amount of setup will fix that. Open all three in a browser now and confirm each one loads.

One thing to check first (ask whoever set this up)

Signing in uses Google. For that to work, this specific web address has to be registered with Google beforehand. If test 1 shows a Google error page mentioning "redirect_uri_mismatch", that registration is missing — it is a five-minute setup job, not a fault you can fix from your side. Report it and stop.

The tests

1Sign in

Go to https://routely-nine.vercel.app and choose Continue with Google.

What should happen Google asks which account to use. After choosing, you land on a page called Get started.

2Add your website

Press Add website. Give it any name you like, and type your website's address — just the domain, like example.com, not a full page address.

What should happen Your website appears in the list, with its status showing Not connected. That is correct at this stage — nothing is installed yet.

Worked    Problem — note what you saw:

3Install the tracking code (the one technical step)

Press Set up pixel on your website's row. A window opens showing two small blocks of code. Press Copy.

That code needs to be pasted into your website's <head> section, on every page you want to test — including the goal page. How you do that depends on your website:

  • WordPress: most themes have a "header scripts" or "custom code" box in the theme settings, or you can use a free plugin such as WPCode.
  • Wix / Squarespace / Shopify: look for "Custom code", "Code injection" or "Header" in the site settings.
  • A hand-built site: paste it just before the closing </head> tag.

If none of that is familiar, this is the moment to ask whoever looks after your website. Show them this page — it is a routine five-minute job for them.

Save your changes and make sure the site is published, not just saved as a draft.

What should happen Nothing visible changes on your website. Visitors see exactly what they saw before.

Worked    Problem — note what you saw:

4Check the code is really there

Back in Routely, press Next: verify installation. It suggests a page address — you can change it to any page you pasted the code onto. Press Verify installation.

What should happen A green confirmation, then a Done button. Your website's status becomes Connected.

If it says the snippet was not found: the usual causes are that the change was not published, that a caching plugin is still serving the old version (clear the cache), or that the code went onto a different page from the one being checked. Fix and press it again.

5Create an experiment

Press New experiment and work through the six steps. Only three things really matter:

Control URL The full address of the page you have now
Variant URL The full address of the alternative page
Conversion URL The full address of your success page

All three must be on the website you added. Use full addresses including https://.

What should happen You reach a Summary step listing everything back to you.

Worked    Problem — note what you saw:

6The pre-publish check

Press Review & create. Routely runs four checks and shows the results.

What should happen Ticks against all four. Then press Acknowledge & create.

If "Script installation" shows a warning: read it carefully — it names the exact problem. "Returned HTTP 404" means that page does not exist, and you need to correct the address rather than reinstall anything. Otherwise press Set up pixel right there, install the code on that page, then press the refresh button beside it. The check runs again without closing the window.

7Start it running

Your experiment is created as a draft — it is not doing anything yet. Open it and press Publish.

What should happen The status changes to Running.

Worked    Problem — note what you saw:

8Watch it work — the important one

Open a private / incognito window and go to your control page address. Repeat several times, using a fresh private window each time.

A private window matters: Routely remembers each visitor's side of the test on purpose, so a normal window will keep showing you the same one.

What should happen Roughly half the time you stay on the page you asked for. The other half, the address bar changes to the variant page. Both are correct — that is the test running.

Try about eight private windows. You should see both outcomes.

Both outcomes seen    Only ever one — note which:

9Record a success

In one of those private windows, after landing on either page, navigate to your goal page.

What should happen Nothing visible. Routely records it quietly in the background.

Done    Problem — note what you saw:

10Read the results

Back in Routely, open your experiment. Wait a few seconds and refresh the page.

What should happen Visitor numbers appear for both sides, and any goals you reached show as conversions. The numbers should roughly match how many private windows you opened.

11Share the results

On the experiment page, find the sharing section and create a share link. Open it in a private window.

What should happen The results open without asking anyone to sign in, and show only this one experiment — no other experiments, no account details, nothing editable.

Things that look wrong but are not

Please do not report these — they are known and intended.

You only get redirected once per browser Deliberate. A visitor who kept flipping between two pages would ruin the measurement. Use a fresh private window to be treated as a new visitor.
A brief blank moment before the redirect Routely hides the page for a fraction of a second so a redirected visitor never glimpses the wrong page. On a slow connection you may notice it.
"0 of 100,000" tracked users There is no billing yet. That figure is a placeholder, not a real plan limit.
Results take a few seconds Visits are sent in the background and the page does not update by itself. Refresh it.
No "winner" declared Intentional. Routely says which side is currently ahead and states plainly that this is not proof. It will not claim a winner it cannot stand behind.
A goal on a different website records nothing The goal page must be on the same website as the test, and must have the tracking code on it too.

If something goes wrong

A useful report answers four things. Screenshots are worth more than descriptions.

  1. Which test number you were on.
  2. What you did — the exact buttons and the exact addresses you typed.
  3. What you expected, and what actually happened.
  4. A screenshot of the whole window, including the address bar.

Also say which browser you used, and whether you were in a private window. If a message appeared on screen, copy it out word for word — the wording usually identifies the cause immediately.
